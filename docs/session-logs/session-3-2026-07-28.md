## Goal

Quick note from the user: the game viewport should be much larger.
Requested research into common cell width/height conventions for
ascii/glyph roguelikes and roguelites before picking numbers.

## Key decisions

- **Viewport grown to 25x21 cells, cell size kept at 24px** — resolved
  live via `AskUserQuestion` after research. `glyphrogue`'s `cellSize()`
  (`packages/core/src/glyphMetrics.js`) always returns a **square** cell,
  so the relevant genre precedent is square-tile games (CDDA 16-32px,
  Cogmind ~12px) rather than classic ~1:1.4-2 terminal-font aspect
  ratios — glyphkeep's existing 24px was already a sane size within that
  range, so only the visible cell count changed.
- **Root cause wasn't just "viewport too small"**: `SIGHT_RADIUS = 8`
  implies a 17x17 visible diamond, but the old viewport (15x11) was
  smaller than that on both axes, clipping FOV the player should see.
  25x21 clears that with margin when the player is roughly centered.
- **A second, deeper mismatch found during verification, fixed as a
  same-session follow-up (user's call, asked live rather than assumed)**:
  the camera's `deadzone` (3) pins the player at exactly `deadzone`
  screen-cells from the leading edge during sustained one-directional
  travel, regardless of viewport size — so even at 25x21, walking
  continuously in one direction still only showed 3 cells ahead, not the
  full 8-cell sight radius. `deadzone` now reads `SIGHT_RADIUS` directly
  (`src/game.js`) instead of a separate magic number, keeping the two
  values from drifting apart again.
