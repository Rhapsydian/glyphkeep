# Session 5 — 2026-07-28

## Goal

Phase 2: full bestiary + boss. `BACKLOG.md`'s NEXT SESSION pointer named
the scope going in (`ChasesPlayer`/`Flees`/`Guards`, combo enemies,
undead-skewing distribution, Duke Glyphmund) — this session ran it as a
`/dev-session`: kickoff research, a decision session resolving the real
open forks live, three implementation checkpoints, and a phase-end review
before close-out.

## Key decisions

Resolved live with the user before finalizing the implementation plan
(this project's decision-session convention):

- **The engine side was lighter than expected.** Kickoff research (two
  parallel Explore agents) found `ChasesPlayer`/`Flees`/`Guards` already
  ship from `@glyphrogue/core`, fully implemented, tested, and exported,
  and `dispatchExclusive`'s priority/component-filter resolution already
  handles combo-behavior priority as a documented pattern — no new engine
  work needed for the solo behaviors or combo priority itself. The real
  work was glyphkeep-side: a data-driven enemy archetype table, floor
  depth plumbed into the generator, `Guards.post` seeding, and a real Duke
  Glyphmund encounter.
- **Bestiary roster**, arrived at over several rounds of live back-and-
  forth, not decided in one pass: rat/goblin/bandit/mouse (general,
  `Wanders`/`ChasesPlayer`/`Guards`/`Flees` solo), skeleton/wraith (undead,
  deeper floors — wraith redesigned mid-conversation from "flees on sight"
  to "wanders, evasive via high `Defense`, gives a lot of essence when
  killed" after the user flagged fleeing-on-sight as thematically hollow
  for a mindless undead; mouse added to fill the vacated flee-on-sight
  niche, "drops a surprising amount of gold"), plus three combo enemies
  (slime, bandit lookout, ghost).
- **`Defense` now also reduces hit chance**, not just damage — the
  mechanism that makes wraith "hard to hit" without adding a fourth stat
  (`DESIGN.md` explicitly wants to stay lean on stats). A global change to
  the shared `attackRule`, not wraith-specific.
- **Duke Glyphmund: enrage at 50% health, summons cut.** A bespoke
  accuracy/damage bump past the threshold is a complete, testable boss
  fight on its own; summon logic is a second feature's worth of scope
  hiding inside "boss" — logged to `BACKLOG.md`'s deferred items rather
  than built now.
- **Wraith/mouse's essence/gold rewards are noted, not built.** Neither
  essence-banking (Phase 4) nor gold currency (Phase 5) exists yet —
  building an inert reward field nobody reads yet would be dead code.
  Behavior/stat identity shipped; the numeric hookup waits for whichever
  phase builds the system that consumes it.

## Work completed

**Checkpoint 1 — solo bestiary** (`b32249b`): data-driven
`ENEMY_ARCHETYPES` table replacing the single hardcoded `wanderer`
registration; `chasesPlayerPlugin`/`fleesPlugin`/`guardsPlugin` wired in
alongside `wandersPlugin`; `Defense`-reduces-hit-chance in `attackRule`;
generic `Guards.post` seeding in `floor.js`; symbol/palette entries
derived from the archetype table in `game.js`. Found and fixed a real
scheduler hang along the way (see Notes) with a glyphkeep-authored
fallback `TakeTurn` rule (`registerPassFallbackRule`).

**Checkpoint 2 — combo enemies + depth distribution** (`4a3a9ce` +
glyphrogue `2e6d5d7`): slime (`ChasesPlayer` + health-gated `Flees` via a
glyphkeep-only `FleesWhenHurt` marker, since giving slime a real `Flees`
component would also match the stock unconditional `fleesPlugin`), bandit
lookout (`Guards`+`ChasesPlayer`, no custom rule needed) and ghost
(`Wanders`+`ChasesPlayer`, ditto) archetypes. `floorGenerator.js` now picks
enemies from a per-depth eligible pool (`minFloor`/`maxFloor`) instead of
checkpoint 1's placeholder round-robin. Needed a companion glyphrogue
export fix (`fleesRule`, the four priority constants, `DEFAULT_MOVE_COST`)
— also let `rules.js`'s `MOVE_COST`/`PASS_COST` stop independently
redeclaring the same "100" twice.

**Checkpoint 3 — Duke Glyphmund** (`f119837`): floor `FLOOR_COUNT` places
him (`Guards`+`Boss` markers) in the farthest room instead of a stairs
anchor. Win detection moved from `checkForDescent`'s tile-arrival check to
a new `isBossDefeated()` (queries for the absence of a `Boss`-marked
entity), mirroring the existing post-dispatch player-death check. Enrage
folded directly into the shared `attackRule` rather than a second
registered rule — `dispatch()` is additive, so two competing `Attack`
rules would double-resolve the same hit.

**Phase-end review** (`422e1c1` + glyphrogue `2c9d35b`): assessed all
three checkpoints for `glyphrogue` promotion candidates. One genuinely new
finding — no composition primitive exists for additive (`dispatch`)
action types, unlike the solved `dispatchExclusive` story for exclusive
ones, evidenced by all three checkpoints needing "conditionally-scoped
rule composition" and the third (enrage) having no clean tool for it.
Logged in both repos' backlogs with full reasoning; needs its own
dedicated conversation, not decided here. The two `glyphrogue`-side items
explicitly waiting on this phase (move-action resolution, camera/render-
loop as scaffold boilerplate) got no new evidence — neither `moveRule` nor
`game.js`'s render loop changed structurally this phase — noted plainly
and left deferred rather than forcing an artificial second-data-point
framing.

Verified: `node --test` 33 → 57 in glyphkeep (all green throughout, each

## Notes

- **A real scheduler hang, found live.** `floor.js` seeds a `Guards`
  entity's `post` to its own spawn position, so a freshly-spawned bandit
  is already "at post" on turn one — `guardsRule` legitimately returns no
  followOn, which used to spend zero scheduler cost and let
  `scheduler.next()`'s tie-break re-select the same actor forever, hanging
  `api.run()` before it ever reached the player's turn. Froze the dev
  server's tab solid on the very first render — the same failure class as
  session 4's already-fixed empty-scheduler hang, but a different trigger
  (a legitimately-idle actor, not zero actors). Fixed as glyphkeep-authored
  content (a low-priority fallback `TakeTurn` rule guaranteeing every
  turn's forward progress), not in `glyphrogue` — genuinely ambiguous
  where a "minimum turn cost" safeguard should live, logged for its own
  conversation rather than decided solo.
- **Browser tooling was rocky this session.** The built-in Browser pane
  stopped responding entirely partway through checkpoint 1 (every
  interaction timed out with "the Browser pane is not displayed"); the
  user pointed at Claude in Chrome as an alternative, which worked but had
  its own recurring flakiness (CDP screenshot timeouts that turned out to
  be transient — `javascript_tool` execution kept working fine throughout,
  confirming the app itself was never actually hung after the scheduler
  fix landed). Leaned on direct JS execution and dynamic module imports
  against the live page more than screenshots as a result.
- Real `glyphrogue` changes landed this session (`fleesRule`+priorities+
  `DEFAULT_MOVE_COST` export fix, plus the phase-end review's `BACKLOG.md`
  updates there) — per the dual-repo convention, a sibling log exists at
  `glyphrogue/docs/session-logs/session-45-2026-07-28.md`.
