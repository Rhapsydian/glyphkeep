## Key decisions

Resolved live with the user before finalizing the implementation plan:

- **No walkable floor-0 hub zone this phase.** DESIGN.md's floor-0 hub has
  multiple fixtures, but re-reading its phasing showed Glyphelda's shrine
  is Phase 4, Trophy Case/Artifact Cabinet are Phase 6, and Glyphrey as a
  physical NPC is Phase 5/6. Phase 3's loadout screen is a pure UI overlay
  shown once at game start instead — building a real hub now would leave
  most of it as dead space until later phases give it content.
- **Weapon + Armor slots, flat modifiers, no rarity.** Weapon modifies
  both `Attack.value` and the `WEAPON_MIN_DAMAGE`/`MAX_DAMAGE` roll range;
  armor modifies `Defense.value` only. Matches DESIGN.md's "deliberately
  lean, resist a fourth stat" framing; rarity/tiers deferred until there's
  real playtesting evidence they're needed.
- **Plain item catalog, not a `registerEntity` plugin** — same shape as
  the enemy archetype table. Items aren't spawned as world entities until
  Phase 5 floor loot, so there's no current consumer for that machinery.
- **Full `registerScreen`+`openScreen`/`closeScreen` mechanism, not the
  lighter UI-initiated shortcut** — the user's explicit call, overriding
  what `glyphrogue`'s own docs actually recommend for this exact case (see
  Notes). Rationale: a uniform path for any future core-triggered screen
  open (e.g. a key item's scripted "use"), not just player keypresses.
- **Loadout roll is a local utility, not a `glyphrogue` gap.** Sampling 5
  distinct items without replacement is a different operation from the
  engine's internal (unexported) weighted-pick helpers; reopening that
  already-logged, deliberately-deferred item on this one more data point
  would be the premature-generalization risk `.claude/dev-session.md`
  already flags.
